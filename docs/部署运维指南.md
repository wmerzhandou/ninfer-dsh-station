# ninfer 双引擎使用指南（3090 单卡）

> 最后更新：2026-10-24 ｜ 当前默认引擎：**满血版**（开机自启）

---

## 一、架构总览

```
                ┌────────────────────────────────────────────────────┐
                │           codex-model-gateway :18003               │
  dsh ─┐        │  对外统一模型名 qwen3.8-27b-ninfer                    │
       ├─ bili ─┤     ↓ 识别后改写为引擎真实 id 并转发                    │
  codex┘ :8787  │  满血: qwen3.8-27b-full → 127.0.0.1:8092            │
  (bili自管理)  │  日常: qwen3.8-27b-ninfer → 127.0.0.1:8091           │
                └────────────────────────────────────────────────────┘
       bili = billion-context 长上下文压缩层（窗口自动随引擎切换：
       满血 245,760 / 日常 180,224）
```

- **两台引擎显存互斥，同时只跑一台**（24G 显存各吃 ~23.3G）。
- 对外（codex / dsh / 任何 OpenAI 客户端）**永远只用** `http://127.0.0.1:18003/v1` + 模型名 `qwen3.8-27b-ninfer`，切引擎对客户端完全透明。
- LAN 访问网关： `http://<本机IP>:18003/v1`，需带 `Authorization: Bearer <~/.codex/gateway.token>`。

## 二、日常操作（记住 3 个命令）

| 操作 | 命令 |
|---|---|
| 看状态 | `ninfer-mode status` |
| 切满血版（249K, 236-321 tok/s, 视觉） | `ninfer-mode full` |
| 切日常版（180K, 98 tok/s, 更省电） | `ninfer-mode daily` |
| 一屏监控 | `ninfer-ctl mon`（或菜单 `ninfer-ctl` → 按 4） |
| 性能快照 | `ninfer-ctl snap` |
| 引擎日志 | `ninfer-ctl logs`（自动跟当前引擎） |
| 全部停止 / 启动 / 重启 | `ninfer-ctl stop` / `start` / `restart` |

`ninfer-ctl` 菜单里按 **7** 切满血、按 **8** 切日常，零记命令。

## 三、重启电脑后会发生什么

| 服务 | 开机自启 | 说明 |
|---|---|---|
| ninfer-serve-full（满血引擎） | ✅ 已启用 | 开机约 2 分钟自动就绪 |
| codex-model-gateway | ✅ 已启用 | 开机自启 |
| billion-context(:8787，codex压缩层) | ✅ 已启用 | 开机自启 |
| dsh-web（浏览器版） | ✅ 已启用 | 绑定 192.168.1.100:13080（默认局域网 IP，可用 DSH_LAN_IP 环境变量改），本机+局域网都能访问；**token 每次重启会变**，双击桌面「启动dsh」图标自动取最新并打开浏览器，地址同时写入桌面 dsh-web地址.txt |
| ninfer-serve（日常引擎） | ❌ 禁用 | 避免和满血抢显存；要用手动 `ninfer-mode daily` |

**重启后小白使用流程**：等 3 分钟 → 双击桌面「启动dsh（AI对话）」→ 浏览器自动打开 → 选模型聊天。同事用：照桌面 dsh-web地址.txt 里的最新地址在自己电脑浏览器打开。详见 `~/dsh使用-小白指南.md`。

## 四、监控面板说明

`ninfer-ctl mon`（= `ninfer-mon`）：

```
服务: active   GPU(利用率%/显存): 97%, 23340MiB/24576MiB   14:32:01
⚡进行中: running 1 (prefill 0)  waiting 0   5s预填 1580 tok/s   host KV 41%
近30请求: 缓存命中率 83%   平均TTFT 12.4s   平均prefill 1420 tok/s   平均decode 236 tok/s
req#12    TTFT    3.2s  prefill    1893 tok/s  decode   238 tok/s  缓存   97.0%
```

- **缓存 %**：本轮 prompt 命中 KV 缓存的比例。>90% 意味着秒回。
- **TTFT**：首 token 延迟。缓存命中时 ≈ 0.5-2s；大段新内容按 ~1,500 tok/s 估算（10 万 token 新内容 ≈ 70 秒）。
- **decode**：出字速度，满血版 236（原创）-321（复述）tok/s。
- **host KV %**：显存中 KV 池占用。接近 100% 时旧会话缓存会被逐出。
- 数据来自 journalctl，监控自动识别当前跑的是哪台引擎。

## 五、dsh / codex 接入

- **dsh**：两个入口任选——`ninfer-local`（Qwen3.8-27B NInfer Q4）和 `ninfer-full`（Qwen3.8-27B FULL 249K）。**两个名字都已注册进 bili 压缩层**（`qwen3.8-27b-ninfer` 与 `qwen3.8-27b-full` 等价，网关两个名字都路由到满血引擎），超过 245K 都有 billion-context 智能压缩兜底。dsh 会自动带上 billion-context 插件，无需配置。
- **codex**：`~/.codex/config.toml` 里 `[model_providers.bili]` → `http://127.0.0.1:8787/v1`，模型 `qwen3.8-27b-ninfer`，**原有配置不受影响**。
- 其它程序（LAN）：`http://<IP>:18003/v1` + Bearer token，模型名 `qwen3.8-27b-ninfer`。

## 六、满血版深度实测（2026-10-24，dsh 全链路）

模拟真实 dsh 会话：**一个会话里逐轮追加材料**（1,980 条工单，每轮提问都考更早的内容），走完整链路 `客户端 → bili:18787 → 网关:18003(改写) → 满血:8092`。

| 轮次 | 可见上下文 | 缓存命中 | 本轮新增 | 全程耗时 | 等效prefill | decode | 考点回答 |
|---|---|---|---|---|---|---|---|
| R1 | 15,365 | 0 | 15,365 | 6.8s | 2,263 tok/s | 163 tok/s | ✔ |
| R2 | 51,544 | 15,444 | 36,100 | 18.5s | 1,950 tok/s | 200 tok/s | ✔ 跨轮引用 |
| R3 | 113,760 | 51,612 | 62,148 | 45.5s | 1,365 tok/s | 139 tok/s | ✔ memo要点 |
| R4 | 172,171 | 113,820 | 58,351 | 59.1s | 987 tok/s | 115 tok/s | ✔ 第700号细节 |
| R5 | 207,270 | 172,242 | 35,028 | 43.4s | 806 tok/s | 122 tok/s | ✔ E1500 |
| memo复述 | 207,365 | **207,339 (99.99%)** | 26 | **1.3s** | — | 169 tok/s | ✔ 逐字存活 |

**结论：**
1. **逐轮追加材料时，永远只对"新增部分"做 prefill**——旧上下文 100% 命中 KV 缓存（见每轮"缓存命中"列正好等于上一轮可见量）。上下文涨到 20 万 token 的过程中，每轮等待 = 新增量 ÷ 800~2,200 tok/s。
2. **回到已读完的材料提问 ≈ 秒回**：207K 时命中 99.99%，全程 1.3 秒。
3. prefill 速度随上下文变长从 2,263 降到 ~800 tok/s（注意力计算物理规律），这是单卡 3090 的正常表现。
4. 满血窗口 245,760：本次实测到 207,270 仍全量缓存；245K 内行为一致，只比 207K 稍慢。
5. 并发仍为 1（`--max-concurrency 1`）：一个请求在跑时，第二个请求排队等待，不会被拒绝。

## 七、故障排查

| 现象 | 处理 |
|---|---|
| 429/显存错 | 确认没两台同时跑：`ninfer-mode status`；多余的一台 `systemctl --user stop ninfer-serve-full`（或 ninfer-serve） |
| 引擎没响应 | `journalctl --user -u ninfer-serve-full -n 50`（日常引擎把 unit 名换成 ninfer-serve） |
| bili 报模型不存在 | bili 窗口与引擎不匹配，重跑一次 `ninfer-mode full`（或 daily）即可自动对齐 |
| 网关 401 | LAN 请求补 `Authorization: Bearer <token>`（token 在 `~/.codex/gateway.token`） |
| 想开 2 并发 | 改 `deploy/engine/run-full.sh` 的 `--max-concurrency 2`（KV 池缩到 ~237K，每 lane 约 150-300MiB） |
